Setup

Everything runs on one Windows PC next to your DCS server: the server itself, the SRS server and Buddy's Radio Ops. Pilots install nothing.

The program files aren't published yet. This guide is for groups testing Buddy Radio.

What you need

A PC that can host DCS. Speech recognition runs on the processor whenever someone talks, so a stronger CPU means quicker replies.

Memory
16 GB at least, 32 GB is comfortable with a big mission like Foothold.
Software
DCS World Server, the DCS-SRS server, and Python 3.11 or newer.
Claude API key
From console.anthropic.com with a few dollars of prepaid credit. A busy evening with five pilots costs well under a dollar.
Optional
A Discord server for target and greenie-board posts, and a tablet for the live map.

Install

  1. Turn on External AWACS Mode in SRS

    In the SRS server settings, switch External AWACS Mode on and set a password for each coalition. The Buddy stations join SRS this way, like an AWACS client.

  2. Let missions talk to Buddy

    Open Scripts\MissionScripting.lua in the DCS server's install folder and comment out three lines, so the block reads:

    sanitizeModule('os')
--sanitizeModule('io')
--sanitizeModule('lfs')
--_G['require'] = nil
_G['loadlib'] = nil
--_G['package'] = nil

    DCS updates put this file back. If the log ever says attempt to index global 'lfs', make the edit again.

  3. Copy Buddy into the server profile

    Put the Buddy folder in Saved Games\<server profile>\Scripts\ and buddy_bridge_hook.lua in Scripts\Hooks\. The hook loads the bridge into every mission, including campaigns like Foothold. Restart the DCS server once so it picks up the hook.

  4. Install Python and the packages

    Install Python from python.org and tick "Add Python to PATH". Then in PowerShell:

    pip install anthropic faster-whisper piper-tts av numpy sounddevice keyboard pypdf

  5. Store your API key

    The key never goes in a file. This asks for it without showing what you paste:

    $s = Read-Host "Paste your Anthropic API key" -AsSecureString
[Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($s)), "User")

    Keep auto-reload off in the Anthropic console, so the credit you bought is the most you can spend.

  6. Connect Discord (optional)

    Create webhooks for a #targets and a #greenie-board channel (Server Settings, Integrations, Webhooks) and store each address the same way, as BUDDY_DISCORD_TARGETS and BUDDY_DISCORD_GREENIE. Test with python discord_post.py targets "Hello".

  7. Start in this order

    The DCS server running a mission, then the SRS server, then Start Overlord.bat in the Buddy folder. The window lists every station under "On the air" and prints the address of the tablet map. The first start downloads the speech model and voices.

Change the stations

Every station lives in stations.json next to the program. Change a frequency or voice, add a tower for another airfield, or remove a station you don't use. Restart Radio Ops after editing.

{
  "type": "tower",
  "name": "Ramat David Tower",
  "airfield": "Ramat David",
  "freq": 250.950,
  "mod": "AM",
  "voice": "en_US-ryan-medium"
}

Put the live map online

On your home network the map is at the address Radio Ops prints. To open it from this website, Radio Ops needs a secure public address. A tunnel gives it one without opening ports on your router.

  1. Pick an access key

    Add a line to stations.json so only people with the key see your mission:

    "map_key": "pick-any-word"

  2. Start a tunnel

    Either Cloudflare (free, new address every time):

    cloudflared tunnel --url http://localhost:8080

    or Tailscale Funnel (free, the same address every time):

    tailscale funnel 8080

  3. Connect the map

    Open the live map, choose Connect, and paste the https address the tunnel printed and your key. Share the link it gives you with your group.

When something's wrong

You seeWhat it means
no DCS data yetNo mission is running, or the bridge didn't load. Check the DCS log for "BuddyBridge started"; if it's missing, redo step 2 and restart the server.
Cannot reach the SRS serverStart the SRS server first, and check srs_server in stations.json.
(not for Buddy) in the logThe station heard a call that wasn't addressed to it. The text shows what it heard, which tells you if the name got clipped.
Port 10081 is busyAnother copy of Radio Ops is already running. Close it.
A station says "say again"It couldn't make sense of the call. Read the rx line to see what it heard, and keep calls short.
